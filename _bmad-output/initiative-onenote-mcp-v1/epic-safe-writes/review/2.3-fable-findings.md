## High

- **H1. "Write grant alone" reaches further than you decided.** Your Q3 (c) answer was about page writes. But AD-7 step 1 and AD-21's Binds now say any write in a protected section runs on the write grant alone. A later hierarchy move (epic 3) or merge could then carry a protected page out of its section, after which the read tools read it with no read grant. Fix: limit the rule to the four page-write tools AD-21 lists, say moves and merges out of a protected section belong to epic 5 or 3, and add a Deferred row.
- **H2. Page edits would fail on any change anywhere on the page.** Introduced by a review fix I asked for. AD-17 now compares "every OE hash the basis supplies". A read returns hashes for every OE on the page, and callers pass the basis back whole. So another writer's text edit in an Outline you didn't touch would make your edit `StaleWrite`. A resize there wouldn't, which is inconsistent. See Q2 below.

## Medium

- **M1.** The read-back step doesn't say what it does for `delete_page_content`, which sends nothing to compare. Fix: for a delete it checks only that the Outline is gone.
- **M2.** "Writes blind" reads as "can overwrite". In practice a write with no read grant can only add: it can't know any `objectID`, so the whole-Outline check refuses anything else. Fix: one sentence in AD-21 saying so.
- **M3.** Restore of a protected entry whose section is "no longer protected" is marked not retryable. If the user protects it again at the same path, the restore would work. Fix: retryable after the user protects it again.
