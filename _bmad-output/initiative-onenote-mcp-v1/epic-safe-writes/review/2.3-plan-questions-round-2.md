# 2.3 plan, round 2: does a write grant include reading protected sections?

Your answers to Q1, Q2 and Q4–Q8 are now Decisions in the plan. Q3 is still open, because your answer ("a write grant automatically grants read") reverses two earlier decisions of yours. I'd like you to choose with the trade-off in front of you.

**What it collides with:**
- **AD-21's grant scope** (yours, 2026-11-06): one protected section at a time. A notebook can't be read-granted as a whole, and a write grant doesn't grant reads.
- **Decision 3** (2026-11-09): a write in a protected section needs both grants.

**Why scope matters more than permission level.** Write already includes read everywhere except protected sections: reads need no grant at all (AD-6). The only open question is the protected sections. A write grant covers a whole notebook, and the dialog asks you to type the notebook's name. If it also granted reads, typing "Notebook A" once would let the model read every protected section in Notebook A that's unlocked, for as long as the grant lasts (write grants never expire). Today each protected section needs its own dialog, which names that section, and the grant can be as short as 5 minutes. So the bigger grant would quietly widen the smaller one.

Your Q5 answer (create_page needs the read grant) also assumes the read grant stays separate.

:::question
**Q3 (again): writes inside a password-protected section.**
- (a) Keep both grants, as decision 3 says. The write grant comes first and then the section's read grant, both asked in AD-7 step 1 before the lock. A write grant never opens a protected section for reading.
- (b) A notebook's write grant also grants reads of every protected section in it. This reverses AD-21's scope and decision 3, and makes Q4 and Q5 moot.
- (c) Between the two: in a protected section, the write grant alone lets the write run, including its own internal reads (step-3 read, read-back, snapshot), which never return content to the model. Read tools still need the section's read grant, so without one the model writes blind (with `noBasis`). Q5 then becomes "no read grant needed".
- (d) A section-level write grant: the protected-section dialog offers "read" or "read and write", so the write needs the notebook's write grant plus a section grant that includes write. Biggest change: a new grant kind in AD-10 and AD-21.

Recommended: (a). (c) is the one I'd consider: it keeps reads per section, but it lets the model overwrite a protected page it can't see. A whole-Outline replace sent without a basis deletes whatever it leaves out, and only the journal recovers it.
