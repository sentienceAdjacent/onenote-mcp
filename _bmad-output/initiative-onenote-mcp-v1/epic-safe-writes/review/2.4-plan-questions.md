# 2.4 plan: questions before the tracer build

The plan is beside this folder (`../story-tracer-create-page-through-the-write-pipeline-plan.md`). Most of it follows straight from AD-6, AD-7, AD-9, AD-10 and AD-18 as 2.3 amended them. These choices are open. The plan runs about 2,600 tokens, over the 1,600 guide (Q9).

:::question
**Q1: `create_page`'s arguments.** `CreateNewPage` takes a section ID and a page style: `default` (the section's own template, which may add content), `blankPageWithTitle` or `blankPageNoTitle`. A title or content would need `UpdatePageContent`, which is a `PageWrite` (2.7, 2.9).
- (a) `sectionId` plus an optional `style` with all three values, defaulting to `default`, so OneNote behaves as when the user clicks Add Page.
- (b) The same, defaulting to `blankPageWithTitle`, so later recipes always start from the same empty page XML.
- (c) `sectionId` only, always `blankPageWithTitle`.

Recommended: (b)
:::

:::question
**Q2: where the new page's ID goes in the result.** `meta` holds a read tool's scalar result today (`parentId`, `path`, `link`). `restore_from_journal` (2.11) also reports a new page, and epic 5 creates sections.
- (a) `meta.pageId`. Epic 5 adds `meta.sectionId` for its creates.
- (b) `meta.objectId`, one field for every create and restore.

Recommended: (a)
:::

:::question
**Q3: the version bump.** Adding a tool is a contract change, so AD-14 bumps the minor version. 2.5 is also a contract change, and no release is planned between them (inception decision 5).
- (a) `0.9.0-rc.1` now, contract `0.9`; 2.5 rides on it unless a release ships in between.
- (b) `0.9.0-rc.1` now, and 2.5 bumps again to `0.10`.

Recommended: (a)
:::

:::question
**Q4: does `grant --write` ask for confirmation?** In AD-6's dialog the typed name is the proof that a person answered. The CLI also takes the name as an argument, which may be pasted from the model's own suggestion.
- (a) After the name matches, show the notebook's displayed name and its path, and ask the user to type `yes`.
- (b) No confirmation: a match grants, as in the dialog.

Recommended: (a)
:::

:::question
**Q5: how long a write waits for `Local\OneNoteMcp.Write`.** AD-18 says only that the wait ends in `ComBusy`, retryable. Another write holds the lock for its whole pipeline (up to 120 s), though a create takes well under a second.
- (a) Up to `timeouts.callSeconds` (30 s by default), within the pipeline deadline.
- (b) Up to the pipeline deadline (120 s).
- (c) A fixed 10 s, like the settings mutex.

Recommended: (a)
:::

:::question
**Q6: the two-process integration test.** Two real `OneNoteMcp.exe` processes over stdio, each with a temporary `settings.json` granting MCP Test only, fire concurrent `create_page` calls. Each server logs every lock hold (correlationId, precise UTC acquire and release times; no names), and the test checks that no two holds overlap. Each run adds about ten empty pages to MCP Test.
- (a) Put them in a dedicated `Create tests` section of MCP Test that the suite creates through the guard, and leave them; you empty it by hand when you like.
- (b) As (a), and soft-delete them at the end through the guarded seam (`DeleteHierarchy`, not permanent). That method isn't probed until epic 5.
- (c) Put them in the existing `Seed` section and leave them.

Recommended: (a)
:::

:::question
**Q7: the `NewerSchema` advice (deferred from epic 1).** A `settings.json` written by a newer OneNoteMcp makes writes fail `SettingsInvalid`, today with `retryable: true` and "Fix settings.json, then retry", which is wrong for that case.
- (a) `retryable: false`, and a `userAction` saying a newer OneNoteMcp wrote the file: update this one (the plugin) and restart the client; don't edit `settings.json`.
- (b) The same `userAction`, but `retryable: true`, since a retry works after the update.

Recommended: (a). With (b) the model may retry in a session that still runs the old server.
:::

:::question
**Q8: an ID that isn't a section, or a section in the recycle bin.** Validation reads the target at step 3. `InvalidArgument` isn't built until 2.5, and AD-9 lists neither case under it.
- (a) `ObjectNotFound` before COM, as OneNote's own `hrSectionDoesNotExist` would say, with a `userAction` asking for a section's ID; a section with `isInRecycleBin` or `isDeletedPages` is refused the same way.
- (b) Refuse only a non-section; let `CreateNewPage` itself answer for a recycle-bin section (likely `hrRecycleBinEditFailed`, mapped `Internal` until 2.7).
- (c) Refuse nothing; pass every ID to `CreateNewPage` and map what OneNote returns.

Recommended: (a)
:::

:::question
**Q9: plan size and the skill and README.** The plan is about 2,600 tokens. The packaging tests fail unless the skill and the README name every contract tool, so both must mention `create_page` now; 2.12 writes the recipes and the grants, limits and journal sections.
- (a) Keep the plan whole. Skill: a `create_page` row, a rule to call it only when the user asks for a page, and the intro no longer says read-only. README: a tool row and a `grant --write` line.
- (b) Keep the plan whole, and write the README's grants section in full now.
- (c) Split: the CLI and the settings writer first, the pipeline and tool second. The tracer's verify then needs both stories.

Recommended: (a)
:::
