- (decision) Stack [ADOPTED by Phill 2026-11-03]: C# .NET 10 + ModelContextProtocol 2.3.1, hand-declared [ComImport] IApplication. First build story is a vtable smoke test; fallback to the GAC PIA if it fails. Binds every unit to one language/runtime; prevents a mixed or Python host.
- (decision) Paradigm [ADOPTED by Phill 2026-11-03]: ports and adapters with a single-STA actor. MCP tools -> use cases -> IOneNoteGateway port; ComGateway (one STA thread, queue, timeouts, reconnect, idle release) is the only code that touches COM; pure XML model has no COM. Prevents stories spinning their own threads or COM objects.
- (direction) Scope (Phill 2026-11-03): target the full COM surface (~27 Application methods + Windows/events), delivered in rounds; v1 = core read/write (hierarchy, page CRUD, append/edit, section create/rename, delete, search). Design must not need rework to add later rounds.
- (decision) Page content contract [Phill 2026-11-03]: raw OneNote 2013 XML in both directions; no markdown/intermediate format. Binds every read/write tool to one representation; prevents per-tool formats and lossy round-trips.
- (direction) Phill 2026-11-03: wrap the MCP in a Claude Code skill; part of its job is prompting the user to allow notebooks not yet allowed.
- (decision) Access model [Phill 2026-11-03]: every notebook is readable; writes need a per-notebook grant. The server enforces the allowlist (not the skill). Grants come only from the user: MCP elicitation where the client supports it, else a user-edited config file; no tool lets the model grant itself access. Prevents a skill-only or model-grantable gate.
- (decision) Write safety [Phill 2026-11-03]: before every page write the server validates the XML against the 2013 schema and checks every objectID it references exists on the page as read just before (read-compare-write). Prevents silent overwrite via a wrong objectID under UpdatePageContent's partial-update semantics.
- (decision) Read default [Phill 2026-11-03]: page reads exclude binary content unless the caller asks. Prevents multi-MB base64 responses by default.
- (question) Is moving a page or section done via UpdateHierarchy reparenting? Not probed in spike 1; verify in the build story that adds move.
- (question) Claude Code elicitation support (v2.1.76+, third-party sources only): confirm against Anthropic docs and test in the first build story; fallback is the config file.
- (decision) Grants [Phill 2026-11-03]: one grant per notebook, persistent until revoked, stored in a config file under %APPDATA% that the skill can show. Permanent delete needs a separate second grant per notebook.
- (decision) Tool shape [Phill 2026-11-03]: thin, roughly one MCP tool per COM method, raw XML in and out. Server-added behaviour only for the access check, search post-filtering, and one uniform error shape mapping HRESULTs to actionable errors. Prevents task-specific tools drifting from the XML contract.
- (decision) Task-shaped tools [Phill 2026-11-03]: allowed later as a layer on top: recipes in the skill first; promoted to a server use case when common or needing atomicity. They compose thin use cases through the same gateway and access check; never bypass them.
- (direction) Phill 2026-11-03: wants recovery for destructive operations, e.g. back up to the file system before anything that skips the recycle bin.
- (decision) Recovery journal [Phill 2026-11-03]: snapshot the target page's full XML (with binary) before EVERY write; retained N days; a restore tool re-applies a snapshot (content recovery, not identity-preserving undo). Location defaults under %LOCALAPPDATA%, user-configurable; stored compressed. Permanent delete of a section/notebook first backs up via Publish in OneNote format; refuse the delete if backup fails.
