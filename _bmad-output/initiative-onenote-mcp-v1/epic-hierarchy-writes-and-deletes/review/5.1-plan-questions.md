# 5.1 Write probes, part 2: plan questions

The plan is beside this folder (`../spike-write-probes-part-2-hierarchy-delete-and-backup-plan.md`). Its Matrix has one row per question the findings doc must answer; together they settle the five spine Deferred rows that name epic 5 (whole-notebook delete, section-group permanent delete, a soft delete in a protected section and a protected section deleted whole, `Publish` as the backup, and the date `DeleteHierarchy` accepts).

**How it runs.** Like 2.2: opt-in scenarios in `tests/OneNoteMcp.Integration/WriteProbes/`, extending its code, run in the team lead's session with you present. Steps that need your hands pause with an instruction the team lead relays. No `src/` change. Raw logs and `Publish` output stay outside the repo, and your OneDrive account ID is written `<cid>`.

**What changes in the guard (not a question).** Today `TestNotebookGuard.Contains` accepts the notebook root itself, so a `DeleteHierarchy` on MCP Test's own ID would pass the guard. The plan adds three refusals before any COM call: a delete or rename of the MCP Test or MCP Test Cloud notebook IDs; a delete of anything this run didn't create (so Seed, Probes, the Ballast sections and the cloud pages are safe); and `UpdateHierarchy` XML with any ID outside the test notebooks. Ballast Vault is never touched.

## Q1. A throwaway local notebook

Notebook-level delete can't run on MCP Test or MCP Test Cloud: either would destroy the fixtures. It needs a notebook made for the purpose. Spike 1 already created a notebook with `OpenHierarchy` cftNotebook (row 9), and AD-7's `Create` creates a notebook only "at a path the server checked was empty", which `TestNotebookGuard.EnsureFolderIsOurs` already does. Each run would make two (soft delete may remove a notebook in a way that leaves nothing for the permanent delete).

Naming: your rule lets the repo name only MCP Test, MCP Test Cloud and their sections. A throwaway named `MCP Test Throwaway <stamp>` is our own test name, not a real notebook, but it would be a new name in the repo, so it needs your OK.

:::question
**Q1: who creates the throwaway local notebook for the notebook-level deletes?**
- (a) The probe: `OpenHierarchy` cftNotebook at `%LOCALAPPDATA%\OneNoteMcp-Test\MCP Test Throwaway <stamp>`, after checking the folder is empty. This also answers the Create row's notebook question. The guard accepts it only by that exact name, a path under that folder, and an ID this run created. The name `MCP Test Throwaway` joins the allowed names.
- (b) You, in OneNote (File > New > This PC), at a pause, at a path and name the probe prints. The probe finds it by name and path. The Create row's notebook question then rests on spike 1 alone.
- (c) Neither: skip notebook-level deletes. The Deferred row stays open, and entry 6 can't offer a notebook permanent delete until something probes it.

Recommended: (a)
:::

## Q2. A throwaway cloud notebook

A permanent delete of a OneDrive notebook may delete its OneDrive files, which is the case a user would most want backed up. 2.2's rule was that the suite never creates a cloud notebook. Creating one through `OpenHierarchy` at a `d.docs.live.net` URL has never been tried.

:::question
**Q2: probe notebook-level delete on a cloud notebook too?**
- (a) No, local only. Cloud notebook delete and its backup stay a Deferred row; entry 2 decides whether local evidence is enough.
- (b) Yes. You create `MCP Test Throwaway Cloud` in OneDrive Documents from OneNote at a pause; the probe finds it by exact name and `d.docs.live.net` path, backs it up, soft-deletes it, then permanently deletes it. Afterwards you look in OneDrive's web recycle bin and report what's there (no probe reads OneDrive).
- (c) Yes, and the probe creates it with `OpenHierarchy` at the OneDrive URL. Untested, and it breaks 2.2's never-create rule for cloud notebooks.

Recommended: (b)
:::

## Q3. Protected-section deletes

Two Deferred rows need a section that is password-protected: a soft delete of a page inside it (does COM move it to the recycle bin, refuse, or delete it permanently?), and the section soft-deleted whole (does `encrypted` survive in the recycle bin, locked and unlocked?). COM can't set a password, so you set it. The probe creates a throwaway section with a few test pages, then pauses: you protect it and unlock it. The probe deletes a page; later you lock and unlock it at pauses while the probe reads the recycle bin. Last, the probe backs it up and permanently deletes it.

:::question
**Q3: where should the protected-section delete probes run?**
- (a) MCP Test only: one throwaway protected section, about five pauses.
- (b) MCP Test and MCP Test Cloud: a second throwaway protected section, about ten pauses. 2.2 saw the cloud notebook differ on dates; its recycle bin may differ too.
- (c) Skip. The Deferred rows stay, and `SoftDelete` refuses any delete in a protected section (AD-21's fallback).

Recommended: (b)
:::

## Q4. Does the backup bring the item back?

AD-7 refuses a permanent delete when the `Publish` backup fails. A file existing proves only that `Publish` wrote something. Opening a copy while its original is still open in OneNote may confuse OneNote (the same section twice), so any check runs after the original's permanent delete, which is also the real restore case.

:::question
**Q4: how should the probe check a backup?**
- (a) File only: it exists and isn't empty; its extension, size and how long `Publish` took.
- (b) (a), then after the original's permanent delete the probe opens the backup with `OpenHierarchy` (a path in the probes folder, never a notebook's) and compares its page titles and count, and `encrypted` for the protected one, with the read taken before the delete. Then you close it in OneNote at a pause.
- (c) (a), then you open the backup by hand at a pause and tell the team lead what you see.

Recommended: (b)
:::

## Q5. Publish format

The ticket names `pfOneNote`. The epic says that if this backup route fails, permanent delete of sections, section groups and notebooks is blocked. `pfOneNote` may not accept a notebook or a section group; `pfOneNotePackage` (`.onepkg`) is the other OneNote format.

:::question
**Q5: which Publish formats should the probe try?**
- (a) `pfOneNote` only, as the ticket says. A kind it fails on is blocked.
- (b) `pfOneNote`, plus `pfOneNotePackage` for any kind where `pfOneNote` fails, so entry 2 has a fallback to weigh instead of a block.
- (c) Both formats for every kind.

Recommended: (b)
:::

Recommended: (b)
:::
